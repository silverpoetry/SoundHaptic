# 波形合成与低延迟播放

## 声音为何只能近似触感

真实 LRA/ERM 通过质量块和弹性结构向机身注入机械能；本项目只能驱动扬声器振膜，再依赖
扬声器安装和机身结构把部分能量耦合为触感。因此听到的音调、机身触感和扬声器安全之间
必须折中。持续单频很快会被感知为声音，所以系统交互使用短脉冲和带制动的包络。

## 可选包络

| 波形 | 合成方式 | 适用感受 |
|---|---|---|
| LRA 方波 | 柔化方波 + 边沿窗 | 短促、干净 |
| LRA 反相制动 | 主驱动 + 末段反相 | 收尾更硬 |
| 阻尼脉冲 | 柔化方波 + 指数衰减 | 边缘更软 |
| 双相脉冲 | 正负等面积半波 | 最短制动感 |
| ERM 启停 | 变速基波 + 少量三次谐波 | 更像质量块起停，适合当前目标设备 |
| 正弦波 | 正弦 + 边沿窗 | 对照和扫频 |

所有波形以 48 kHz、单声道、16-bit PCM 生成，最终样本经过软限幅。音量通过
`AudioTrack.setVolume()` 独立应用，基准力度控制 PCM 幅度；二者不是同一个参数。

## 语义相对值

`HapticEffect` 保存每个脉冲的原始时长、力度、延迟和设计波形。用户选择的基准时长与力度
按比例缩放这些值，因此调参不会把所有效果变成完全相同：刻度仍弱于点击，重击仍更强，
清理和锁屏仍保留多段节奏。

当前实现把用户选择的波形作为全局质感覆盖，同时保留语义时长、力度和延迟。新安装默认
ERM 启停、252 Hz、16 ms、38% 基准力度和 31% 轨道音量。

## 低延迟路径

### `system_server`

使用常驻流式 `AudioTrack`。短 PCM 直接写入已经开始播放的流，避免新建 10–16 ms 静态
音轨时功放淡入尚未完成，导致声音在停止瞬间才出现。

### SystemUI 与桌面

使用预热静态轨道池。MIUI `HapticFeedbackUtil` 构造完成后预热轨道，使锁屏或清理等状态
切换前能够开始播放。

### 屏幕生命周期

屏幕交互时保持低成本静音/流状态；息屏一段时间后释放，点亮时重新预热。这样避免无限
后台音轨，同时控制首次交互延迟。

## 调参方法

1. 触感音量从 15–25% 开始；
2. 使用扫频寻找机身反馈明显、但音调和杂音可接受的区间；
3. 再调整基准力度，不要先把轨道音量拉满；
4. 使用 8–16 ms 短脉冲比较边沿和收尾；
5. 最后在键盘、返回、长按和清理等真实场景验证语义层级。

若出现破音、明显拍边、金属刮擦声或扬声器发热，应立即停止并降低音量/力度。
